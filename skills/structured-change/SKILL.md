# Structured Change
State **observable outcome, canonical owner, invariants and proof**. Inspect direct consumers/fakes/tests and establish failing evidence for reproducible bugs when practical. Extend existing API/persistence/runtime/native/UI owners rather than adding duplicate state or policy. Preserve local-first privacy, auth/origin boundaries, cancellation/cleanup, native state restoration, main-thread UI rules and artifact immutability. Use `validate-change` during implementation and `preflight-change` only at integration/release readiness.
